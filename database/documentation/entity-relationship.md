# Entity Relationship Documentation

This document describes the entity relationships, data flow, and database architecture for the RIS Data Scrap system.

## Overview

The RIS Data Scrap database is designed around several core entity groups:
- **Core Entities**: Categories, Products, Retailers
- **Scraping Entities**: Scrape Jobs, Monitoring Schedules  
- **Matching Entities**: Product Matches, Match Groups, Brand Aliases
- **Historical Entities**: Price History

## Core Entity Relationships

### Hierarchical Category Structure

```
categories (self-referential hierarchy)
├── id (PK)
├── parent_id (FK → categories.id)
├── name, name_en
├── path (computed hierarchy path)
└── level (hierarchy depth)

Example Hierarchy:
Electronics (level 0)
├── Air Conditioning (level 1)
│   ├── Split AC (level 2)
│   ├── Central AC (level 2)
│   └── Portable AC (level 2)
└── Appliances (level 1)
    ├── Refrigerators (level 2)
    └── Washing Machines (level 2)
```

### Product-Category-Retailer Relationships

```
products
├── id (PK)
├── category_id (FK → categories.id)
├── retailer_id (FK → retailers.id)
└── [product attributes]

retailers
├── id (PK)
├── code (UNIQUE: HP, TWD, GH, etc.)
└── [retailer attributes]
```

**Relationship Rules:**
- Each product belongs to exactly one category
- Each product belongs to exactly one retailer
- Categories can have multiple products
- Retailers can have multiple products
- Products can exist across multiple retailers (different records)

## Product Matching System

### Match Group Structure

```
match_groups
├── id (PK)
├── name
├── category
└── brand

    ↓ (one-to-many)

product_matches
├── id (PK) 
├── match_group_id (FK → match_groups.id)
├── products (JSONB array)
├── match_confidence
├── unified_name
├── unified_brand
├── unified_category
├── price_range_min/max
└── price_variance_percentage
```

### Product Match Structure

The `products` JSONB column contains arrays of matched products:

```json
{
  "products": [
    {
      "product_id": "uuid-1",
      "retailer_code": "HP", 
      "name": "Samsung 24000 BTU Split AC",
      "price": 35000.00,
      "url": "https://homepro.co.th/..."
    },
    {
      "product_id": "uuid-2", 
      "retailer_code": "TWD",
      "name": "Samsung Split Air Conditioner 24000BTU",
      "price": 34500.00, 
      "url": "https://thaiwatsadu.com/..."
    }
  ]

```

### Brand Alias System

```
brand_aliases
├── id (PK)
├── canonical_brand (standardized name)
├── alias_brand (alternative name)
├── confidence (matching confidence)
└── is_active

Examples:
canonical_brand: "Samsung"
alias_brand: "SAMSUNG Electronics"

canonical_brand: "Mitsubishi Electric" 
alias_brand: "Mitsubishi"
```

## Scraping and Monitoring System

### Scraping Job Lifecycle

```
scrape_jobs
├── id (PK)
├── retailer_code
├── job_type
├── status (pending → running → completed/failed)
├── category
├── total_items, processed_items
├── successful_items, failed_items
├── started_at, completed_at
├── duration_seconds
└── error_message

Status Flow:
pending → running → completed
                  → failed
                  → cancelled
```

### Monitoring Schedules

```
monitoring_schedules
├── id (PK)
├── name
├── retailer_code
├── category
├── frequency (hourly, daily, weekly, monthly)
├── is_active
├── last_run
└── next_run

Scheduling Logic:
next_run = last_run + frequency_interval
```

## Historical Data Tracking

### Price History

```
price_history
├── id (PK)
├── product_id (FK → products.id)
├── price, original_price
├── currency
├── recorded_at
└── source

Relationship:
products (1) ←→ (many) price_history
```

**Price History Rules:**
- Multiple price records per product
- Ordered by recorded_at (time series)
- Used for price trend analysis
- Supports price change alerts

## Database Constraints and Integrity

### Primary Keys
All tables use UUID primary keys generated by `uuid_generate_v4()`

### Foreign Key Constraints
- `products.category_id` → `categories.id` (ON DELETE SET NULL)
- `products.retailer_id` → `retailers.id` (ON DELETE CASCADE)
- `product_matches.match_group_id` → `match_groups.id` (ON DELETE SET NULL)
- `price_history.product_id` → `products.id` (ON DELETE CASCADE)

### Check Constraints
- `scrape_jobs.duration_seconds >= 0`
- `product_matches.match_confidence BETWEEN 0.00 AND 1.00`
- `brand_aliases.confidence BETWEEN 0.00 AND 1.00`
- `price_history.price >= 0`

### Unique Constraints
- `retailers.code` (UNIQUE)
- `brand_aliases(canonical_brand, alias_brand)` (UNIQUE)

## Performance Considerations

### Indexing Strategy

**Core Indexes:**
- `products(sku)` - Product lookups
- `products(brand)` - Brand filtering
- `products(retailer_id, retailer_product_id)` - Retailer-specific lookups

**Matching Indexes:**
- `product_matches(unified_category)` - Category filtering
- `product_matches(price_range_max)` - Price sorting
- `product_matches(price_variance_percentage)` - Variance filtering
- `product_matches(match_confidence)` - Confidence filtering

**Historical Indexes:**
- `price_history(product_id, recorded_at DESC)` - Price trends

### Query Optimization

**Common Query Patterns:**
1. **Product Search**: Filter by category, brand, price range
2. **Price Comparisons**: Join product_matches with aggregated pricing
3. **Price Trends**: Time-series queries on price_history
4. **Scraping Monitoring**: Status and progress tracking queries

## Data Consistency Rules

### Temporal Consistency
- `created_at` ≤ `updated_at` for all entities
- `scrape_jobs.started_at` ≤ `completed_at`
- `monitoring_schedules.last_run` ≤ `next_run`

### Business Logic Consistency
- Products can only belong to active categories
- Scrape jobs must reference valid retailer codes
- Product matches must contain valid product references
- Price history records must have positive prices

### JSONB Data Consistency
- `product_matches.products` array must contain valid product references
- `products.specifications` must follow defined schema
- JSON structures must be valid and queryable

## Scalability Considerations

### Horizontal Scaling Points
1. **Price History**: Partition by date ranges
2. **Product Matches**: Shard by category or retailer
3. **Scrape Jobs**: Archive completed jobs older than threshold

### Vertical Scaling Points
1. **JSONB Indexing**: GIN indexes on frequently queried JSON paths
2. **Full-Text Search**: Implement for product names and descriptions
3. **Materialized Views**: For complex aggregations and reports

## Integration Points

### External System Interfaces
1. **Supabase Client**: Direct database access from FastAPI
2. **Firecrawl API**: External scraping service integration
3. **Frontend API**: RESTful endpoints for web interface

### Data Import/Export
1. **CSV Export**: Product catalogs and price comparisons
2. **JSON API**: Real-time data access
3. **Database Backups**: Regular snapshot creation
